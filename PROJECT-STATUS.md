## Live verification, 2026-09-18

`make smoke-arxiv` was run against the real arXiv API on SK's Mac. The parser
matched the live feed exactly on first contact: ids and versions, cross-listed
categories and primary category, authors, UTC-converted submission times,
abstracts and canonical URLs. The fixtures built from arXiv's published API
documentation were therefore accurate, and the fixture-based tests can be
trusted until the API changes.

One defect the live run exposed that no fixture could have: the API was being
called over `http://`, which answers `301` to `https://`. Because the rate
limiter runs before every redirect hop, that redirect cost a wasted three-second
wait on each page fetch — minutes across eleven sources. `ARXIV_API_URL` now
uses HTTPS directly, and a test asserts the scheme so it cannot regress.

## Decisions and corrections from Sprint 0 Task 3

- **One rate limiter per host, not per source.** Eleven arXiv categories are eleven registry entries but one server. A limiter per source would have issued eleven requests every three seconds and breached arXiv's terms on the first run. `LimiterRegistry` keys on hostname and keeps the strictest interval any source asked for.
- **The User-Agent was only applied to the client the HTTP wrapper built itself.** An injected client fetched anonymously, so the promise to identify ourselves to source operators held only on one code path. Now set unconditionally. Found by a test asserting the header.
- **`log.exception` could crash a run.** structlog's console renderer raises a `TypeError` on exceptions whose args are not plain strings — `ExpatError` from malformed XML is one — so a single malformed feed would have taken down the whole nightly job while trying to log the failure. Errors are now formatted before logging, and recorded on the `fetch_run` row regardless.
- **`external_id` is the versionless arXiv id.** v1 and v2 of a paper resolve to one record rather than two; the version is kept in `canonical_ids`. A revision currently does not update the stored metadata — that is deliberate for Sprint 0 idempotency and is listed as debt below.
- **`ingest_all` takes an injectable client factory**, because the function the CLI actually calls was otherwise untestable without real network access.
- **Scope held to arXiv.** bioRxiv and RSS were considered and deferred: each needs its own parser, and Task 3's acceptance criterion is documents in the database, which arXiv alone satisfies across all six domains.

## Decisions and corrections from Sprint 0 Task 2

- **Repository layout changed** from three distributions under `packages/` to one distribution with subpackages under `src/radar/`. They share a dependency set and ship together, so separate distributions would have bought nothing for the cost of uv workspace tooling. `docs/06` section I.3 updated.
- **`source_document.external_id` is NOT NULL.** PostgreSQL treats NULLs as distinct in a unique constraint, so a nullable column would have let a re-run insert duplicates — defeating the idempotency Task 3 depends on. Fetchers fall back to the canonical URL.
- **`source_document.content_hash` is indexed, not unique.** A unique constraint contradicted `duplicate_of`: syndicated content legitimately arrives from two sources and must be recorded as a duplicate, not rejected. `docs/06` section K.3 updated.
- **CI `pip-audit` audits a compiled requirements file**, not the environment: `--strict` fails on this project's own editable, non-PyPI distribution. Caught by running the CI steps locally before committing.

## Technical debt (known at design time, accepted)

- Single admin token instead of user auth (ADR-0005). Replace in Phase 4.
- Review UI is a table, not a workflow product.
- No trend, alert, report or graph features; schema supports them.
- Staleness computed at read time; fine at MVP scale, may need materialisation later.
- Semantic search is dedup-only in the MVP; ranking fusion is a Should-have.
- Semantic Scholar enrichment deferred to Phase 4 (licence for stored TLDRs unconfirmed).
- Corrections via GitHub Issues rather than an in-app workflow.
- `TimestampMixin.updated_at` uses SQLAlchemy's `onupdate`, so a raw SQL UPDATE bypasses it. Acceptable while all writes go through the ORM; revisit with a trigger if the pipeline ever writes SQL directly.
- No `pre-commit` hooks yet; `make check` covers the same ground manually.
- A revised arXiv paper (v2) is skipped rather than updating the stored record: `ON CONFLICT DO NOTHING` is what guarantees idempotency, but it also means later metadata never lands. Revision handling belongs in Sprint 1, alongside triage.
- Fetcher tests run against fixtures written from the published arXiv API documentation, not against recorded live responses, because this workspace's egress blocks `export.arxiv.org`. `make smoke-arxiv` is the compensating control and should be run whenever the parser changes.
- The daily ingest workflow is scheduled but inert until the `RADAR_DATABASE_URL` and `RADAR_CRAWLER_CONTACT` repository secrets exist; it reports a notice and exits cleanly rather than failing.
